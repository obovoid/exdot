# Contribution Guidelines

Thank you for your interest in contributing to Exdot.

Exdot is still in active development, so language rules, compiler behavior, and APIs may change frequently. Before starting larger changes, please open an issue or discussion first so the idea can be aligned with the current direction of the project.

When contributing:

- Keep changes focused and easy to review.
- Follow the existing code style and project structure.
- Prefer simple implementations over unnecessary complexity.
- Add or update tests when changing compiler or language behavior.
- Document new syntax, keywords, or semantic rules.
- Avoid introducing behavior that weakens Exdot's strict and explicit design.
- Keep Godot-specific behavior separated from general compiler logic where possible.
- Do not make unrelated refactors as part of a feature or bug fix.

Bug reports should include a minimal example, the expected behavior, the actual behavior, and the Godot version it can be used (if applicable).

Pull requests should clearly explain what changed and why. Breaking language changes should also describe their effect on existing Exdot code.

By contributing, you agree that your contributions may be distributed under the project's license.
